# 走天下攻略体系 — 完整生命周期方案（v1.0 设计稿，2026-07-28）

## 0. Context

用户问的 5 块：(1) 攻略怎么生成 / (2) 个人中心是否有「我的计划」 / (3) 「我的攻略」是否有状态机 / (4) 懒人计划 → 图文编辑 / 评价 / 打分 → 发布全链路 / (5) 发布后详情页。本方案回答全部并落到代码改动表。

**起点**（已盘清现状）：
- 攻略有 2 个 create 路径：手动 `/api/guides` (跳过 DFA) + `from-plan/[planId]` (走 DFA)
- 后者**端点存在但无 UI 调用** —— Plan 创建后没有任何"发成攻略"按钮
- `/profile/plans` 完全不存在；sidebar 没 plans entry
- `/profile/guides` 当前 3 tabs (published / drafts / saved)，**未区分** pending_review 与 rejected
- PlanRecord / Guide / ChildRating / ChildSaying / GuideReview 各 model 字段已熟
- 攻略详情页 `/guides/[id]` 不渲染 childSayings / footprints / timelineBlocks 结构化数据

## 0.5 审核方案（用户拍板 — 2026-07-28）

**目标**: 守合规（敏感词 / PII） + 防滥发。**不做质量审核**——质量由社区推荐/勋章体系兜底。

**两层结构**:

**L1 自动 DFA** — 每次 guide submit/publish 必跑, 包括直接 `/api/guides` 路径:
- 敏感词白名单（暴力/赌博/极端/未成年身份信息）→ **hard reject**（直接 rejected，作者可改后重提）
- 软判词（色情/歧视/争议）→ 进 **pending_review** 进人工队列
- 手机/身份证正则 → 命中 ≥3 处 → hard reject，≤2 处 → pending_review
- 长度 ≤ 5000 字 / ≥50 字符；超范围 pending_review
- 复用 `apps/travel-guide/src/lib/moderation.ts` 现有 DFA

**L2 独立 moderation 服务接入** — `apps/moderation/` 跨子站服务, 提供:
- **用户举报**: `/api/moderation/report` (auth) — 任何人点"举报" → 进独立服务队列
- **处罚阶梯**: 该用户全子站 3+ 次违规 → block；level 2 → 24h mute；level 3 → 72h；level 4 → 7d
- **重复检测**: 同用户已 reject 词 → 内容指纹比对
- **跨子站统一**: 论坛/挑战/童言若该用户在论坛有违规, 攻略发布也要叠加
- **admin 队列**: `/api/moderation/review` (auth) 人工处理 pending items

**L3 人工审核** — 仅 L1 软判 + L2 举报触发时才人工处理:
- admin UI: `/admin` 加"TAB · 攻略待审"显示 L1 pending + 路人举报的 pending
- 单个 approve / reject 按钮 (复用现有 `/api/admin/guides/[id]/approve|reject`)
- admin 可写 reject reason (公开显示在作者详情页)

**自动 vs 人工边界**:

```
提交内容
  ↓
L1 DFA 全自动跑
  ├─ 命中 hard reject 阈值 → status=rejected + reject reason → 用户能改后重提
  ├─ 命中 soft 阈值 → status=pending_review → admin "待审" tab 出现
  └─ 通过 → status=published (立即公开)
  ↓
用户举报 (任意时间)
  ↓
L2 进独立服务 report 队列
  ├─ 同时把 guide 改 pending_review (hidden 但可重审)
  └─ admin 看到举报 + L1 soft 合并处理
```

**改动**:
- ✏️ `lib/moderation.ts` — 删 hard-only 简化, 改 dual threshold (严重/软判)
- ✏️ `api/guides/route.ts` POST — 现在直接 status=published 改: submit 时跑 L1；软判 → pending_review
- ✏️ `api/guides/from-plan/[planId]` — 同上对齐（已经跑 DFA，只需改阈值分类）
- 🆕 `api/guides/[id]/submit` — 重提入口 (status=draft|rejected → pending_review, 跑 L1)
- 🆕 `api/guides/[id]/report` — 详情页举报, 转 `apps/moderation` 服务
- ✏️ `app/admin/page.tsx` — 新 "TAB · 待审攻略" 拉 `/api/moderation/review?type=guide`
- ✏️ `app/guides/[id]/page.tsx` — 加举报按钮

**KOL/勋章机制暂不做**: v1 不区分发布者身份, 全部自动 + 异常进人工。

## 2. 锁定的设计决策 (用户拍板 — 2026-07-28)

| # | 决策 | 拍板 |
|---|---|---|
| D1 | 攻略主入口 + 编辑权限 | `/guides/create` + `/guides/[id]/edit`。已发布的攻略：作者可**撤回编辑**→ status=draft；draft/rejected → 编辑；published → 撤回才能编辑 |
| D2 | `/api/guides` 手动路径是否走 DFA | **走**（v1.0 重构，全部路径统一过 L1 DFA）|
| D3 | PlanRecord 状态机 | `draft / confirmed / active / completed / published`（沿用 mobile utils/travel-api.ts）|
| D4 | rejected 状态作者能否编辑重提 | **能**（编辑后 `POST /api/guides/[id]/submit` 重提，跑 L1 DFA 重审）|
| D5 | 发成攻略的交互 | 两种都给：「📝 自动按行程生成」按钮 → 后端组装 + 「✏️ 我要手动写」→ 编辑器空白起 |
| D6 | Published 作者能撤回吗 | **能**（published → draft，重新编辑后重走 L1）|
| D7 | 审核定位 | **合规 + 隐私**（敏感词 / PII / 未成年保护）；**不做质量审核** |
| D8 | 审核流程 | **先自动**（L1 DFA），异常/举报再人工 |
| D9 | 举报功能 | 详情页加举报按钮 → 进 `apps/moderation` 独立服务队列 |
| D10 | `apps/moderation` 服务 | **接入**（之前未接，本 PR 接：`/api/moderation/report` 接入攻略举报, `/api/moderation/review` 进 admin）|
